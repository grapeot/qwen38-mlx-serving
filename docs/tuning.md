# 硬件调优与配置解析 (Tuning Guide)

本指南针对 Apple Silicon 统一内存架构，深入解析 `qwen38-mlx-serving` 的各项配置参数与系统底层内核调优策略。


## 1. 目标硬件平台与基准规格

- **芯片型号**：Apple Silicon M5 Max
- **GPU 核心**：40 核 GPU
- **统一内存**：128 GiB 统一内存 (Unified Memory)
- **操作系统**：macOS (arm64)

> 本配置在 M5 Max 40 核 GPU、128 GiB 机器上筛选；其他硬件的可用性和性能未验证。

## 2. 候选配置

实际配置见 [m5-max-128gb.json](../profiles/m5-max-128gb.json)，由 wrapper 生成原生启动命令，不需要手工拼接引擎参数。

| 配置 | 用途 |
|---|---|
| `--ctx-size 262144` | 主模型输入与输出共享的配置上限；测试只到 128K，完整 262K 尚未测试，Vision 默认禁用 |
| `--max-resident-mem 96GB` | 引擎驻留预算，不等于实际占用或系统预留量 |
| `--kv-quant 8`、`--mtp-head-kv-quant` | 主模型及 MTP 头的 KV8；未做质量等价评估 |
| `--mtp-depth 6`、`MLX_SERVE_MTP_FORCE_DEPTH=3` | CLI 上限 6、实际固定深度 3 |
| `MLX_SERVE_MTP_DRAFT_GREEDY=0` | 采样草稿，保留采用配置 |
| `--mtp-history-window 8192` | 只缩短草稿头历史，历史长上下文速度筛选胜出 |
| `--reasoning-budget 0` | 默认关闭思考，推理题可在请求中明确开启 |
| 不传 `--ple-gpu` | 保持 CPU mmap ngram 路径 |
| `--prefix-cache-entries 4`、`--prefix-cache-mem 4GB` | 正常服务的前缀缓存预算；测试用 entries 0 |

这是历史组合包筛选出的采用配置。截至 2026-10-02，已在完整社区模型上完成 2K–128K 的冷缓存基准测试与 captured llmprobe 重放对照，以及带硬件遥测同步采样的 64K/128K 长上下文专项复测；完整 262K 尚未实测。

## 3. 系统 wired memory 设置

测试机手动使用以下设置：

```bash
sysctl iogpu.wired_limit_mb
sudo sysctl -w iogpu.wired_limit_mb=118000
```

包装器只读取并报告。重启 macOS 后应重新检查。这个数值只用于已测试的 128GB 机器，其他内存规格需重新评估。

## 4. 调优时复测

在相同提示词、采样、输出长度和冷缓存条件下比较配置，同时保留客户端与服务端速率。历史 GPU ngram 配置可加载但没有赢得速度筛选；更深 MTP 也不总更快。

CPU mmap 与 GPU 共享统一内存，不能把 32GB 表当作零物理内存开销。更小内存设备可能连权重都无法加载，不能靠降低上下文保证可运行。

262K 是主模型输入与输出共享的配置上限，实测只到 128K，Vision 默认禁用。

## 5. 风扇与热管理说明

- **风扇控制策略**：默认由 macOS 系统底层调度管理风扇与散热策略，本项目不修改系统风扇策略，不调整内核热控曲线，亦不安装任何第三方风扇控制工具。机器风扇始终由 macOS 默认管理。
- **测量方法与开源边界**：在性能与热管理复测中，使用已有 `macmon` pipe 管道同步采集 GPU 核心频率、温度与功耗；风扇转速 (RPM) 通过本机 SMC 接口执行只读采样。为保障开源仓库整洁与安全边界，不在公开仓库中提交私有传感器实现、SMC 探针脚本或机器原始日志。原始逐请求与遥测记录保存在状态目录（`~/.local/state/qwen38-serving/long-context-retest/RUN_ID/`，不记录个人绝对路径）。
- **传感器采样性质**：在基准测试期间获取的 GPU 温度、频率、功耗与风扇转速读数均为瞬时采样值，反映测试当下的瞬时物理负载，而非系统进入保护状态的恒定阈值。
- **复测现象与严谨结论**：
  - 在带传感器同步记录的 64K 与 128K 长上下文复测（同配置服务重启、64K/128K 交替运行、每请求后 45 秒空闲、冷前缀缓存）中，64K 与 128K 的 Decode 速率中位数分别恢复至 97.5 tok/s 与 100.6 tok/s，未观察到更换模型权重后持续一致的 Decode 退化。
  - **既不能确认也不能排除此前热降频**：复测高负载期间风扇明显升速（128K 最大转速达到 4900–5300+ RPM，64K 升至 4500–4800+ RPM），GPU 峰值温度达 97.6°C，GPU 忙碌率超过 50% 的负载采样中，各请求的频率中位数为 1144–1220 MHz。由于上一轮完整重放未同步记录温度与频率数据，且本轮复测同时改变了服务实例、执行顺序（64K/128K 交替）和等待间隔（45 秒空闲），因此现有数据既不能确认、也不能排除上一轮长上下文下降是由热降频所致，**不写热问题已解决**。
  - **测试与性能边界**：macOS 的 `pmset -g therm` 未显示 warning 并不证明硬件没有发生动态调频。本次复测仅验证了在特定交替与空闲协议下长上下文的吞吐表现，不能保证任意任务或无空闲高负载下均能达到 100 tok/s；持续无空闲高负载、完整 262K 上下文以及广泛生成质量基准均未经过验证。
